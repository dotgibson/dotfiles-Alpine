# dotfiles-Alpine/install/packages.txt
# apk package names for the modern terminal stack. One per line; # comments ok.
# Most modern tools live in the `community` repo — make sure it's enabled in
# /etc/apk/repositories (it is by default on Alpine 3.x + edge).
# A few tools are NOT listed here and are built from source in bootstrap.sh instead:
# tealdeer (testing-only, cargo) plus duf, glow and sesh (go install) — all four are
# testing-only or unpackaged on Alpine, so listing them would only break bulk install.
# starship (since v3.21) and yazi (since v3.22) recently landed in `community`. NOT
# tree-sitter-cli or viddy: both have been in `community` since v3.17 — what is recent
# about those two is that *this repo* stopped source-building them, not Alpine's packaging.
# All four are apk-installed below, with bootstrap keeping a source build as a fallback.

# ── shell + multiplexer ───────────────────────────────────────
bash           # bootstrap.sh is a bash script; a fresh Alpine ships only busybox ash,
               # so `apk add bash` is a PREREQUISITE to run it (see README) — declared
               # here too so a full provision keeps it installed
zsh            # Alpine's default shell is ash — zsh must be added explicitly
tmux

#   source via `cargo install --locked tealdeer` in bootstrap.sh (see header).
atuin          # shell history (in Alpine repos — no installer needed)

# ── recently promoted to `community` (were bootstrap source-builds until v3.24) ──
# apk installs the native musl build first; bootstrap.sh's cargo/curl blocks are now
# fallbacks that skip when apk already provided the binary. Three of the four are
# presence-guarded; tree-sitter-cli is the exception and is version-guarded, because:
#
# The community tree-sitter-cli IS the musl build on every branch, but it only CLEARS
# nvim-treesitter's >=0.26.1 floor on v3.24 (0.26.7-r0) and edge (0.26.7-r1). v3.21 ships
# 0.24.4-r0 and v3.22/v3.23 ship 0.25.10-r0 — all three BELOW the floor. Keep the name
# listed anyway: it resolves on all five branches and is the right build on the two where
# it clears. The version guard is what covers the three older branches — a presence guard
# would see apk's 0.25.10, skip the build, and leave the box below the floor in silence.
# The floor lives in one place: TREESITTER_FLOOR in bootstrap.sh.
starship       # prompt (musl build in community; official installer kept as fallback)
yazi           # file manager (community; cargo build kept as fallback). In `community`
               # only since v3.22 — NOT on v3.21 (supported to 2026-11-01), where this
               # name is the one that aborts the bulk `apk add` (see the retry note below)
tree-sitter-cli  # nvim parser CLI (see note above)
viddy          # watch replacement (Core aliases watch->viddy, HAVE_VIDDY-guarded)

# ── modern CLI extras (core-doctor parity; community repo) ─────
# Most of core-doctor's modern-CLI set is in `community` on current stable. The
# exceptions are duf + glow: still `testing`-only (NOT in `community` on stable),
# so they are deliberately NOT listed here — bootstrap.sh installs them from source
# via a `command -v`-guarded `go install` (static, musl-safe), which is their REAL
# source, not a mere fallback.
# Do NOT add them back "as a best-effort": apk fails the whole transaction on one
# unknown name, so a permanently-unresolvable entry makes the bulk `apk add` in
# apk_install() fail EVERY run, forcing the per-package retry loop for all ~50
# packages. The fallback is for names that might be missing on some boxes, not for
# ones known to be absent on all of them.
# apk_install() (bootstrap.sh) is resilient — a name missing on this box (e.g. `sd`
# if it hasn't landed) is skipped per-package, never fatal.
dust           # du (dust)
procs          # ps
gron           # greppable JSON. In `community` only since v3.23 — NOT on v3.21 or v3.22
               # (supported to 2026-11-01 / 2027-05-01). Not a rename and not a drop: it
               # was promoted from `testing` later, so leave the name alone. On those two
               # branches gron (and yazi) fail the bulk `apk add`, and apk_install() falls
               # back to the per-package loop for all ~60 names — noisy every run, never
               # fatal (bootstrap.sh skips per package). Verified 2026-08-21.
gum            # shell-script UI toolkit (charm)
xh             # HTTPie-style HTTP client
doggo          # dig / DNS client (in community — no go install needed)
gping          # ping with a graph (core-doctor `data / net` row)
lnav           # log file navigator (core-doctor `data / net` row)
carapace       # multi-shell completion engine (in community — no go install needed)
sd             # sed-style find & replace (in community)
yq-go          # mikefarah Go yq — packaged as `yq-go`, provides `cmd:yq`.
               # Do NOT use plain `yq` (that's the Python kislyuk yq, a different tool).
# Opt-in companions: Core only wires these up when present (HAVE_DIFFT / HAVE_ASTGREP),
# so they're additive, not required. Both are first-class musl builds in `community`
# (no cargo/go fallback needed), so they belong in the apk list rather than bootstrap.
difftastic     # structural git diff (difft) — gated by Core on HAVE_DIFFT
ast-grep       # AST-aware structural search/rewrite (`ast-grep`) — gated by Core on HAVE_ASTGREP

lazygit

shellcheck     # shell linter

# ── clipboard — OPTIONAL: pulls X/Wayland libs. On a headless/container Alpine

# ── build toolchain (needed to compile yazi + tree-sitter-cli on musl) ────────
build-base     # Alpine's gcc/g++/make/musl-dev meta (replaces Fedora's gcc/gcc-c++/make)
cargo          # rust toolchain (pulls rust)
go             # go toolchain — REQUIRED for the duf/glow/sesh `go install` fallbacks in
               # bootstrap.sh. Without it those fail every run (with a one-line hint each):
               # the mise fallback resolves `go@latest` to mise's go *backend* (a module
               # installer), never installs a runtime, and dies with "couldn't exec
               # process". `go` is in community.
pkgconf        # some crates probe libs via pkg-config at build time
openssl-dev    # ditto — common cargo build dependency

# ── headers for mise's source builds of node/python/ruby (musl) ──────────────
# On musl, mise flips `all_compile` to true by DEFAULT (a mise-side default, not a
# setting in core/mise/config.toml): every precompiled runtime it would otherwise
# fetch — nodejs.org's tarballs, python-build-standalone, the jdx/ruby prebuilts —
# is glibc-linked and cannot run here. So node/python/ruby are always COMPILED on
# Alpine, and each compile needs the -dev headers below. Without them `mise install`
# (and the daily `mise upgrade` in core/maint/dotfiles-maint.sh) fails every run with
# three source-build errors and the three runtimes stay `(missing)` in `mise ls`:
#   node   → deps/uv/src/unix/udp.c: fatal error: linux/errqueue.h  (linux-headers)
#   python → zipimport.ZipImportError: can't decompress data; zlib not available,
#            plus _ctypes/_curses/readline/_bz2/_lzma/_zstd/_uuid "missing"
#   ruby   → yaml.h not found (psych), "missing libffi" (fiddle), zlib not configured
# build-base + openssl-dev above are already required and cover the rest.
# Deliberately NOT listed: tk-dev. It only supplies Python's _tkinter and drags in
# the X libs this file keeps optional (see the clipboard note) — a headless Alpine
# should not pull an X stack to build an interpreter nothing runs a GUI on.
linux-headers  # kernel uapi headers — node's bundled libuv includes linux/errqueue.h
zlib-dev       # python zlib (ensurepip dies without it) + ruby zlib ext
libffi-dev     # python _ctypes + ruby fiddle
yaml-dev       # ruby psych (yaml.h) — the YAML ext Bundler/RubyGems need
readline-dev   # python readline + ruby's interactive line editing
ncurses-dev    # python _curses / _curses_panel  (the runtime `ncurses` is listed below)
bzip2-dev      # python _bz2
xz-dev         # python _lzma
zstd-dev       # python _zstd (new stdlib module in 3.14)
sqlite-dev     # python sqlite3
gdbm-dev       # python _dbm / _gdbm
util-linux-dev # python _uuid (libuuid)
